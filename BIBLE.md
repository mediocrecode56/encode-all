# Encode All: bible

Native Windows downloader, converter and remuxer around yt-dlp, FFmpeg and FFprobe. Workspace rules: `E:\CODING\BIBLE.md`. Last verified: 2026-11-21 (1.0.5).

## Rules (never break)
- The yt-dlp step is always bit-for-bit: format IDs picked in `src/dl/ytdlp.cpp`, merged or remuxed with `-c copy` only (never `--recode-video`, `--force-keyframes-at-cuts`, `--audio-format` or filters). Original stops there (native container, MKV for mixed families).
- MP4 and MOV (owner's decision, 2026-11-20) then convert in our own FFmpeg step: H.264 or H.265 at CRF 12/14/16 (extreme/high/normal), preset `slow` (NVENC p6), with the encoder setting below. Video already in the chosen codec is copied. MP4 audio: AAC copied, else AAC 320k. MOV audio: copied if MOV holds it, else exact PCM. The queue labels the result COPY or LOSSY.
- AAC everywhere is named by its stereo rate (`aacKbpsFor`: mono half, surround a quarter per channel, max 512k) at a rate AAC stores (`aacSampleRate`: over 96 kHz becomes 48 or 44.1). MP3 is stereo at most, 48 kHz at most. 4:2:0, 4:2:2 and DNxHR crop odd sizes to even (the encoders round silently otherwise); 4:4:4 keeps them. A rotation tag is applied before any size math. Any filter, crop or depth/chroma drop makes a lossless encode LOSSY.
- Encoder (owner's decision, 2026-11-20): every encode (Convert and downloads) uses `Settings::encoder`, default Auto = the fastest that works here (NVENC, Quick Sync, AMF, then x264/x265; `pickEncoder`). It is chosen only in Settings, never per job; runners read it from `c.settings`. Lossless stays on x264/x265 unless NVENC is pinned. A hardware failure retries once in software.
- Remux (owner's decisions, 2026-11-20 and 2026-11-21): MP4 or MOV only (no MKV). Audio: Original (copy; exact PCM only where the container cannot hold a track), Linear PCM for every track (exact, 16, 24 or 32-bit float), or AAC 128/192/256/320k (lossy, labelled; AAC tracks stay copied). Each track can still override.
- Audio only: MP3 320 CBR is a labelled lossy transcode (MP3 sources are copied); WAV decodes exactly (f32 for lossy sources, source depth for lossless); Original copies the stream. A download that is converted is fetched as `<name>.src.<ext>` and removed after verification.
- Never overwrite: every output goes through `uniquePath` and a `.tmp` name, renamed only after verification: every output stream matches the plan's `expect` (type, codec, size, depth, chroma, channels, rate; `checkExpect`), the duration matches, and the start and end decode. Never drop a stream silently: every excluded or unsupported stream is listed in the plan.
- Performance first: no timers while idle, relayout only on change (a diff of the item list repaints only changed rectangles), FFmpeg at below-normal priority, all work off the UI thread. Runners read task specs through `RunCtx::spec()`/`specSet()` (queue lock), never `t.spec` directly.
- UI: monochrome, white on black (dark) or black on white (light). Segoe UI 13 px for labels and boxed controls (buttons, checkboxes, dropdowns, segments, solid progress bars); Consolas 12 px for technical lines (streams, plans, logs, numbers). No colours, no animation. Compact scale (owner's request, 2026-11-21: 30% smaller): `S()` and the menus' sizes are design units of 0.7 px at 96 dpi (`kUiScale` in `gfx.h`); fonts and icon glyphs are sized on their own for readability (owner, 2026-11-21: 1.0.3 was too small), so never shrink them with the scale. Widths that hold text are measured (`tw`), never fixed. Icons are GDI+ anti-aliased with whole-pixel strokes (`Painter::icon`); icon buttons carry a `tip` shown in the header's hint line.
- Sections (owner's decision, 2026-11-21): no queue panel. Download, Convert and Remux each have a bar at the top (links; files by click or drop), their options, then one list holding every item before and after it starts (`collectRows`: pending items and that kind's tasks, newest first by `order`; a started item keeps its `order`/`orderSub` in the spec, so it stays in place). Every row: start/pause/resume/retry, open (link, or play the file), folder, remove/cancel; "start all" at the list's top right. A click unfolds the row's details (segment, plan, tracks, result, log). Row actions look their row up again by `RowId` when they run (`withRow`). The playlist RANGE box speaks playlist numbers (`YtEntry::index`, what rows show), never list positions (`rangesText`/`applyRanges`).
- UI grammar: bold section titles; rows with a fixed label column (`fieldLabel`, mid ink, upper case); lists scroll with a thin mark (`scrollbar`) and say what to do when empty (`emptyState`). Buttons are lower case; "download all" (convert all, remux all) carries its icon (`iconButtonText`). Row starts: download icon on links, arrow on files, play only resumes. Row second lines are short (`briefMedia`, `Selection::brief`); the full plan and log stay in the details. History, log and settings are line icons (`Painter::icon`) at the far right of the DOWNLOAD/CONVERT/REMUX row. Every dropdown, menu and confirmation is the app's own popup (`src/ui/menu.cpp`: `runMenu` with `#` section titles and one check per section, `runConfirm`), never `TrackPopupMenu`, native menus or `MessageBox`; edit boxes get the app's cut/copy/paste menu. Only the shell file and folder pickers stay native. Convert (owner's request, 2026-11-21): PRESET row (four presets, then one saved-presets dropdown), TARGET row (target, quality, speed, audio), PICTURE rows (size, frame rate, pixels; then deinterlace, rotate, denoise, sharpen), SOUND row (channels, loudness, sample rate for audio targets), each its own dropdown with "clear", options on the SAVE TO row. `relayout()` never nests (`building_`): setting an edit's text during a build sends EN_CHANGE.
- Tests never share the app's data: `integration_tests.exe` calls `setDataDir(build\test-data)`. Never put a `portable` file in `build\` (that made `build\EncodeAll.exe` show test tasks, history and log lines).
- Updates never touch running tasks: tool swaps wait until the tool is idle; app updates are staged and used on the next start. Closing the app keeps running tasks (`interrupted`): they come back waiting, and downloads keep their `.part` files.

## Layout
- `src/core`: UTF-8/path helpers, JSON, processes (job objects, kill tree, suspend), WinHTTP, SHA-256.
- `src/media`: `probe` (ffprobe JSON), `compat` (container matrix, advice), `encode` (convert/remux plans, presets, estimates, warnings), `hwenc` (encoder detection by test encodes).
- `src/dl`: yt-dlp info parsing, format choice, args, progress and error classes.
- `src/app`: settings, `deps` (tool manager), `queue` and `runners`, `appupdate`. `src/ui`: window, painter (line icons), views, the in-app menu (`menu.cpp`), thumbnails.
- Data: `%LOCALAPPDATA%\Encode All` (settings, presets, queue, history, log, `deps\<tool>\current|previous|new`). A `portable` file beside the exe keeps data in `data\` there.

## Dependencies (downloaded at first run, never bundled)
- yt-dlp: `yt-dlp/yt-dlp` latest `yt-dlp.exe` against `SHA2-256SUMS`; nightly (`yt-dlp/yt-dlp-nightly-builds`) only after an extraction failure on the latest stable.
- FFmpeg/FFprobe: `yt-dlp/FFmpeg-Builds` `latest/ffmpeg-master-latest-win64-gpl.zip` against `checksums.sha256`. Deno (yt-dlp's JS runtime): `denoland/deno` zip + `.sha256sum` (PowerShell format; `extractHash` reads it).
- Each install: download, verify, unzip with `%SystemRoot%\System32\tar.exe`, self-test, then `current` moves to `previous`. Checks compare published checksums only (no GitHub API). A rollback skips the build it left until a newer one appears.
- YouTube thumbnails use `i.ytimg.com/vi/<id>/mqdefault.jpg`: the sized `sqp=` ones can be WebP, which clean Windows cannot decode.

## Build and test
- `.\build.ps1` (WinLibs g++, CMake, Ninja from TOOLS; static; an empty `build\nomanifest\default-manifest.o` keeps WinLibs' default manifest out, so the exe has one manifest) builds `build\EncodeAll.exe`, `unit_tests.exe`, `integration_tests.exe`, and copies the exe to the project root (`EncodeAll.exe`, git-ignored, not portable: it uses `%LOCALAPPDATA%\Encode All`). Owner's rule (2026-11-20): every update and release leaves its latest exe there; if that copy is running, close it and build again. `-Release` also stages `build\stage` (portable) and writes `dist\`. This PC can crash compilers under load: re-run once before debugging an internal compiler error.
- `build\unit_tests.exe`: logic, under a second; run on every change.
- `build\integration_tests.exe [--no-net]`: tools install through the app's own manager into `build\test-data` (never the app's data), then real media (remux packet hashes, lossless frame hashes, exact PCM, NVENC/QSV, pause/resume/cancel/retry/restart), the matrix (edge-case fixtures through every target, audio mode, filter and Remux mode; each output independently probed and decoded to the end without an error) and live downloads (bit-identical to the raw formats, MOV, 4K AV1 segment to H.264 MP4, MP3, segment, playlist). About 5 minutes with network. Lavfi `testsrc2` rounds odd sizes to even: odd fixtures use `testsrc`.
- `tests\update-test.ps1`: fake 9.9.9 build (`-DEA_VERSION_OVERRIDE`) served locally (`EA_UPDATE_BASE`): tampered package refused, swap, rollback after failed starts (`--update-now`, `--startup-check`). Pipe GUI-exe calls (`| Out-Null`) so PowerShell waits for them.
- GUI checks run in WinTest's hidden Sandbox, never on the owner's desktop: `E:\CODING\WinTest\WinTest.ps1 launch encodeall` (fixture `build\stage`). The guest has network and a vGPU (NVENC, Quick Sync work). `ui click --at` takes screen coordinates (add the window origin from `ui inspect`); Ctrl shortcuts need `send-keys --via send-input`. A screenshot of the app window leaves out an open dropdown: find its `EncodeAllMenu` window with `ui list-windows` and screenshot it with `--window`. To open a file in the guest, run the guest's `EncodeAll.exe <file>` with `exec` (it hands the file to the running window).

## Release
- Version lives in `src/version.h` (`EA_VERSION`, `EA_VERSION_W`, `EA_VERSION_NUM`) and CHANGELOG.md; build.ps1 passes it to the installer. Bump the last position on every committed change.
- Publisher: GitHub Actions `release.yml` on a pushed `v*` tag builds, runs unit tests and uploads `EncodeAll-Setup-<v>.exe`, `EncodeAll-<v>-win64.zip` and `SHA256SUMS` to `mediocrecode56/encode-all` (public). Pushes to `main` only build and test.
- Steps: `.\build.ps1 -Release` (refreshes the root `EncodeAll.exe`), unit, integration and update tests, WinTest launch check, CHANGELOG, commit, `git tag v<version>`, `git push origin main v<version>` (needs the owner's yes), then confirm the release is not a draft and has all three assets.
- App update: zip verified by SHA256SUMS, `EncodeAll.exe` renamed to `.old`, new exe moved in and used on the next start; a third start that never reached "healthy" (15 s) restores `.old`.
